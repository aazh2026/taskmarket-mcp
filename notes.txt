READ-ONLY, PROVABLY
- server.js parses its own argument vector before every CLI call and refuses
  anything that is not `task list` or `task get`. The check is in code, not in a
  comment.
- There is no submit, accept, bid, rate, post-task, claim, withdraw or
  sign command anywhere in the source. Grepping the file for those verbs finds
  only the mode descriptions and one field name.
- The server never reads a private key, never writes a keyfile, never stores a
  credential, and holds no state between calls.
- It speaks stdio only: it opens no listening port and makes no outbound
  request of its own. The only process it starts is `taskmarket task list` or
  `taskmarket task get`.

EARLIER ENTRIES I LOOKED AT, AND HOW THIS ONE DIFFERS
This task had 59 public submissions at the time of writing (read with
`taskmarket --network tempo task submissions 0x7c03bf7ec59b598f3ce220407d377a72da76ef99046245659a6c74c53e366cdd`).
The public submission bodies were not exposed through that command — it returns
ids and reference codes only — so I did not read the other entries' text and am
not claiming to have compared against them.

What is different about this one, stated plainly:

1. The reward filter is exposed in the units people actually think in.
   The CLI's `--reward-min` counts whole tokens (1 means 1.00 OUSD), which is
   easy to get wrong. The server accepts `min_reward_tokens` (1 = 1.00) and
   `min_reward_base_units` (1000000 = 1.00) and converts, so a caller does not
   have to know the CLI's unit. I hit that exact bug while building this and
   fixed it in the server rather than in the documentation.

2. Every result carries a `reward_token` field naming the chain's stablecoin
   (OUSD on Tempo, USDC on Base), so a caller never has to infer from the chain
   name which token a reward is in.

3. `get_task` accepts a `TSK-` reference code as well as a `0x` id, and tries
   each supported chain in turn. The CLI's own `task get` only resolves
   reference codes for listed tasks; the server's fallback makes a single-task
   lookup work the same way from any client.

4. A failed lookup returns an MCP error result with the underlying CLI message
   instead of throwing, so an assistant can show the reason to the user rather
   than the client seeing a transport error.

5. The transcript is a real captured session from the SDK's own client against
   this server, with the matching CLI output printed next to each call, so a
   reviewer can check the parity claim by running one command
   (`node transcript-run.mjs`) rather than by reading prose.

FACTORY-FRESH CHECKOUT
To run this entry from a clean checkout:

The one command in the README (`npm install -g taskmarket-mcp`) installs the
server; `npm install` inside the checkout installs the single dependency. The
server needs the Taskmarket CLI on PATH, which the README states.
